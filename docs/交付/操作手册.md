# 操作手册（运营后台）

面向运营、营养、厨房、财务四类使用者。所有操作都在 http://<host>:5174 的后台完成。

---

## 0. 登录与角色

| 账号（初始） | 角色 | 能做什么 |
|---|---|---|
| admin / admin123 | 超级管理员 | 全部 |
| ops / ops123 | 运营 | 菜单、订单、券、credit、复核、厨房只读 |
| finance / finance123 | 财务 | 退款、冲正、成本、定价、审计 |
| auditor / auditor123 | 只读审计 | 日志与报表只读 |

**部署前必须改密**；同一账号不得多人共用（手册 §14）。

越权操作会被后端拒绝并提示「当前角色（xx）无权执行该操作」。

## 1. 每周菜单

### 1.1 新建与编辑

1. 进入「每周菜单」→「新建周菜单」；
2. 填写主题（如「东京主题周」）、地区、**开始日期必须是周一**、版本号；
3. 创建后进入详情页，逐日点「编辑餐次」，为早/午/晚选择菜品版本；
4. 保存后系统自动重算当日重量、蛋白、营养点。

> 菜单未发布前可反复修改；**一旦发布即冻结**，只能新建版本。

### 1.2 发布前检查

点「发布前检查」，逐项查看：

| 检查项 | 不通过时的处理 |
|---|---|
| 21 个餐次配置完整 | 补齐缺失餐次 |
| 菜品版本与 BOM 完整 | 为菜品建版本、补 BOM |
| 营养与全天重量在允许范围 | 调整菜品组合（阈值见配置 `meal.menu-check`） |
| 过敏原、保存、复热、配送批次完整 | 补菜品信息 |
| 预计食材成本率未超预警线 | 调整菜品或定价 |
| 厨房设备与产能 | **人工确认**项，不阻断发布 |

「未通过」会阻止发布；「人工」项仅提示。

### 1.3 发布

检查通过后点「发布」。发布后：

- 小程序「本周/下周」立刻可见；
- 该版本不可再改；
- 已锁定的历史订单价格与内容不受影响（有快照）。

## 2. 菜品与菜谱 BOM

进入「菜品与食材」页面，分两个标签：

**食材**
1. 点「新建食材」：名称、分类、采购/使用单位、换算率、**可食率**、移动加权价、保质天数、过敏原；
2. 已有食材可编辑或删除（删除需确认）。

**菜品**
1. 点「新建菜品」：名称、分类、保存方式、复热方式、额外过敏原；
2. 在列表点「版本 / BOM」打开抽屉；
3. 点「新建版本」：净重、热量、蛋白、碳水、脂肪，并逐行添加 BOM（食材 + 可食生重）；
4. 保存后系统按 `采购价 × 可食生重 ÷ 可食率` 自动算单份成本，版本号自动递增。

> 没有版本与 BOM 的菜品无法排进菜单；已发布菜单引用的版本不能被修改。

> 成本口径的关键：**可食率**填错会直接导致成本与毛利失真。

---

## 3. 定价版本

1. 「定价版本」→「新建版本」，填写基础日价 66、含基础蛋白 60g、加量单价 1.90/10g、最低日价 65、蛋白范围 80–220；
2. 在该版本下添加**替换选项**（原餐次 → 替换餐次），**审核即冻结成本**；
3. 点「复核」记录复核人，再点「发布」；
4. 发布后：新计划用新价格，**已确认订单不变**。

> 已发布版本不能改，也不能追加替换选项；改价请新建版本。

---

## 4. 复核事项

用户计划里出现以下情况会生成待办：

| 类型 | 含义 |
|---|---|
| 蛋白越界 | 原始目标超出 80–220g，已按边界生成草稿 |
| 份量触界 | 某餐缩放超出 0.5–2.0 倍 |
| 价格兜底 | 日价触发最低价 65 元 |

处理：在「复核事项」点「处理」填写说明。**只要还有未处理事项，该用户就无法下单**。

## 5. 订单与配送

- 按状态/服务日筛选；点「详情」查看餐次、金额、定价版本、配送批次；
- 锁单由定时任务每日 12:00 执行（次日订单）。失败原因会显示在订单上（如余额不足）；
- 需要补跑时用接口 `/admin/meal/orders/lock-run`；
- 配送：详情里点「开始配送 / 完成」，标记批次状态；
- 退款：详情右下「退款」，资金**按原来源**退回（套餐回套餐、现金回现金）；
- 导出：工具栏「导出配送清单」得到当日 CSV。

---

## 6. 厨房生产

1. 选服务日 → 「生成生产批次」（按已锁订单合并，可重复执行）；
2. 查看批次（计划份数、实做、报废）与食材需求（理论可食重量、采购重量、成本）；
3. 「登记产量」填实做与报废；「登记领料」填实际用量与损耗；
4. 导出「生产单」「分装标签」交给厨房与分装人员。

> 标签含订单号、批次、餐次、菜品、克重、蛋白、过敏原、联系人。

---

## 7. 成本报表

1. 选日期区间 → 「查询」；
2. 看每日的实收、三层成本（食材/包装/配送）、手续费、固定成本、毛利与成本率；
3. 底部「成本参数」可在线调整包装、配送、手续费率、固定分摊；
4. 「理论用料（已登记）/ 实际用料 / 用料差异」三列用于看**领料损耗**：
   - 只统计已登记领料的食材；
   - 差异为正表示超领，需追查切配或报废。

> 参数是初始假设，真实收费前需经营方确认。

---

## 8. 用户与余额

> **credit 有效期规则（内部体验期）**：本阶段发放的 credit **不过期**，不做到期提醒，
> 也不按过期资金处理；正式付费阶段再单独制定充值、退款与有效期规则。

1. 输入用户 ID → 查询余额（总/套餐/现金）与流水；
2. 「发放 credit」：必须填原因，用户端只显示为「账户余额」；
3. 「人工调整」：调增/调减，必须填原因；
4. 错误只能「冲正」，不能删除流水。

> 赠送的 credit 退款时只回套餐余额，不会变成现金。

---

## 9. 审计日志

记录发放、调整、退款、冲正、菜单发布、定价发布、复核处理七类动作，含操作人与时间。只读审计角色可查，运营不可见。

---

## 10. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 发布按钮报「检查未通过」 | 看检查详情，按失败项修 |
| 用户说无法下单 | 查「复核事项」是否有待处理 |
| 订单一直「待锁定」 | 看 `lockFailReason`；多为余额不足 |
| 导出 CSV 打开乱码 | 用 Excel「数据 → 从文本」选 UTF-8；文件已带 BOM，正常应直接可读 |
| 替换选项里没有菜 | 该餐次没有已审核的替换选项，需在定价版本里加 |
