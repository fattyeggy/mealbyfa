## 四、本轮整改验收

| 项 | 验收标准 | 实测结果 |
|---|---|---|
| P0 微信真实登录 | 真机两账号独立；体验环境无法自编 code 登录 | 服务端 `jscode2session` 已接；**prod profile 下自编 code 返回「未配置微信 AppID/AppSecret」**；真机两步待验 |
| P0 后台账号 | 新库不生成已知密码账号；演示账号停用 | **prod profile 下 `admin/admin123` 登录失败**（未建号）；日志仅提示配置环境变量，无明文密码；本地仍有 4 个演示账号 |
| P1 截止与补跑 | 11:59 可下单、12:00/12:01 拒绝；补跑不重复扣款 | `OrderDeadlineTest` 4 例通过；**14:36 下明天的单被拒**，提示「已于 2026-11-15 12:00 截止」；锁单补跑幂等已有测试 |
| P1 优惠券结算 | 有券/无券金额与账本一致；失效券提示 | 试算 80 → 抵扣 10 → 应付 70；下单携带 `couponId`；券失效返回原因并提示重新确认 |
| P1 配送状态粒度 | 一次操作只更新一条实际配送 | 按 `deliveryId` 更新；实测完成晚餐后早餐/午餐仍为 `PENDING` |
| P1 快照来源边界 | 下单后换菜单、重建计划，旧单仍锁原菜单 | 订单保存 `source_menu_id/version`，锁单只读订单来源；自动化用例覆盖该顺序 |
| P2 访客周菜单 | 未登录可切换本周/下周并滑动看每日菜单 | 切换、访客浏览、主题文案、空态已具备；**左右滑动未实现** |
| VI | 双端使用「发发的餐 / meal by fa」与指定色值 | 小程序首页、导航标题、应用名与后台侧栏/登录页均已更新；logo 已入库 |

## 六、复现命令

```bash
# 1) 测试
cd backend && source ../scripts/env.sh && mvn clean test    # 123 项

# 2) 本地启动（mock 登录 + 演示账号）
java -jar target/sancan-meal-service.jar --server.port=8080

# 3) 演示数据
python3 scripts/demo/demo-menu-seed.py http://127.0.0.1:8080
python3 scripts/demo/demo-plan-seed.py http://127.0.0.1:8080
python3 scripts/demo/demo-order-seed.py http://127.0.0.1:8080

# 4) 体验/生产配置
java -jar target/sancan-meal-service.jar \
  --spring.profiles.active=prod \
  --spring.datasource.url=jdbc:mysql://127.0.0.1:3306/sancan \
  -DWX_APP_ID=... -DWX_APP_SECRET=...   # 实际用环境变量注入

# 5) 前端
cd miniapp && npm run build:h5 / build:mp-weixin
cd admin && npm run build
```
