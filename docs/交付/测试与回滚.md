> 已解决：菜品/食材后台界面（工作说明 17）、备份恢复演练（见下）。
>
> **本轮整改已关闭的缺陷**（工作说明 19，均有真实接口验收）：
> 1. 同一优惠券可进入多张订单 → 改为数据库条件更新预占（RESERVED），并发只成功一次；
> 2. A→B→A 价格无法回到原价 → 原始 baseCost 不再被替换覆盖，差价始终相对原始餐次；
> 3. 配送只有订单+批次、无法表达跨日早餐 → 增加 serviceDate / actualDeliveryDate / deliverySlot
>    与 `meal_delivery_item`，D 日早餐归属 D-1 晚餐批次；
> 4. 历史订单快照不完整 → 计划保存来源菜单，快照含 BOM/营养/过敏原/成本，且只插入不更新；
> 5. 配送状态一次更新两条不同日期的记录 → 改为按 deliveryId 精确更新；
> 6. 旧订单可能锁到新计划的新菜单 → 订单保存来源菜单，锁单只读订单来源。

## 4. 回滚方案

### 4.1 代码回滚

1. 发布前保留上一版 `sancan-meal-service.jar`（命名带日期）；
2. 回滚：停止服务 → 用旧 jar 启动 → 验证 `/ping` 与登录；
3. 前端同理：保留上一版 `dist/` 目录，回滚即替换静态文件。

### 4.2 数据库回滚

- 升级前**必须**完成 `mysqldump` 全量备份；
- `migration-p4.5-p4.6-mysql.sql` 只**新增**表与列（另含 `DROP TABLE meal_pricing_rule`），
  旧代码可忽略新增列，**不必回滚结构**；
- 若必须回滚：恢复备份到新库 → 服务指向新库 → 验证后切换。

### 4.3 业务回滚

| 场景 | 处理 |
|---|---|
| 定价发布错误 | **不能回退版本**。新建一个与旧参数一致的版本并发布；已确认订单价格不受影响 |
| 菜单发布错误 | 已发布菜单不可改；新建版本并发布替换，历史订单仍有快照 |
| 误发 credit | 用「人工调整（调减）」并填写原因；账本留痕 |
| 误退款 | 重新发放等额 credit（需原因）；原退款流水不可删 |

### 4.4 备份恢复演练记录（2026-11-15）

在 MariaDB 13.0.2 上完成：

1. 全量导出：`mariadb-dump --single-transaction sancan_drill > drill.sql`；
2. 恢复到新库 `sancan_drill_restore`；
3. 校验：29 张表一致；`meal_menu_meal` 21 行、`meal_dish_version` 3 行、`meal_order` 1 行、
   `meal_wallet_ledger` 3 行、`meal_audit_log` 4 行，逐表行数与 `CHECKSUM TABLE` 全部一致。

导出耗时 0.4s、恢复 1.4s（演示数据量级），恢复后服务可正常启动。
