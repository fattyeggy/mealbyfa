## 1. 本轮修复的四个 P0

### 1.1 一券多用（资金）

券状态改为数据库条件更新：

- 下单：`UPDATE ... SET status='RESERVED', used_order_id=? WHERE id=? AND user_id=? AND status='UNUSED' AND end_time>NOW()`，影响行数为 0 直接失败；
- 锁单：只允许本订单 `RESERVED → USED`（校验 `used_order_id` 与有效期）；
- 取消/退款：只释放 `used_order_id` 匹配本订单的券。

真实接口结果：

```
同一张券第二单 → 1305 优惠券状态不可用：RESERVED
并发两单       → 成功 1 / 尝试 2
锁单失败       → 券仍为 RESERVED；取消后变 UNUSED
```

### 1.2 连续替换价格（资金）

`baseCost` 不再被替换覆盖，始终保存最初默认餐次成本；当前成本存 `cost`。
差价始终按「当前 − 原始」计算。

真实接口结果：**75 → 82 → 75**，换回后 `swapDifference=0`。

### 1.3 配送履约模型（履约）

- `meal_delivery` 增加 `service_date`、`actual_delivery_date`、`delivery_slot`；
- 新增 `meal_delivery_item` 关联配送与订单餐次；
- 规则：D 日早餐 → D−1 日晚餐批次；D 日午餐 → D 日午餐批次；D 日晚餐 → D 日晚餐批次；
- 生产汇总、分装标签、食材需求统一按「履约日 D = 午餐 D + 晚餐 D + 早餐 D+1」口径。

真实接口结果：一个订单生成 3 条配送，早餐 `BATCH_2` / `actualDeliveryDate=前一天`。

### 1.4 历史订单快照（合规）

- 计划生成时保存 `source_menu_id` / `source_menu_version`；
- 锁单按计划来源菜单构建快照，不再查最新发布菜单；
- 快照含菜品版本、BOM、营养、过敏原、保存复热、成本、定价明细；
- 快照只插入，无更新/删除入口（新增只读查询接口）。

真实接口结果：发布新定价版本后，快照 payload 与订单金额**完全不变**。

### 1.5 拒绝下单无副作用

真实接口结果：余额 435 → 435，生产批次 0 → 0，券状态不变。

## 2. 微信凭据接入

| 项 | 处理 |
|---|---|
| AppID | 写入 `miniapp/src/manifest.json` 的 `mp-weixin.appid`，构建产物 `project.config.json` 已带 AppID |
| AppSecret | 只写入 `backend/.env.local`（chmod 600，`.gitignore` 已忽略），不进仓库、不进文档 |
| 启动脚本 | 新增 `scripts/run-local-wx.sh`：H2 + 关闭 mock + 注入真实凭据 |
| 凭据校验 | 用伪造 code 调 `jscode2session`，返回 **40029 invalid code**（而非 40125 密钥错误）→ AppID/Secret 有效 |
