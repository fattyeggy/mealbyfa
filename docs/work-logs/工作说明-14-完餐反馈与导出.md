## 2. 完餐反馈

### 2.1 数据与接口

`meal_feedback`：一单一餐一条（`(order_id, meal_type)` 唯一），记录剩余比例、饱腹感 1–5、训练状态与备注。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/app/orders/{orderId}/feedback` | 提交单餐反馈 |
| GET | `/app/feedback/week?date=` | 周复盘（按日 + 汇总） |
| GET | `/admin/meal/feedback?serviceDate=` | 后台按服务日查看 |

### 2.2 关键规则：送达才可反馈

不是「有订单就能评」，而是**该餐次所属配送批次已送达**（或服务日已过）：

- 早餐与晚餐属 `BATCH_2`，午餐属 `BATCH_1`；
- 未送达返回 `1600 该餐次尚未送达，暂时不能反馈`；
- 重复反馈返回 `1601`。

这条规则把「配送状态」和「反馈」真正连了起来——后台点「完成配送」，用户端才能评分。

### 2.3 周复盘口径

```
进食率 = Σ(吃完 1.0 / 剩四分之一 0.75 / 剩一半 0.5 / 未吃 0) ÷ 反馈餐次数
平均饱腹感 = 有评分餐次的均值
低饱腹感餐次 = 评分 ≤ 2 的条数
```

## 3. 导出

| 接口 | 内容 | 权限 |
|---|---|---|
| `GET /admin/meal/kitchen/export/production` | 服务日/批次/菜品/计划/实做/报废/状态 | 厨房读 |
| `GET /admin/meal/kitchen/export/labels` | 订单号/批次/餐次/菜品/克重/蛋白/过敏原/联系人 | 厨房读 |
| `GET /admin/meal/orders/export/delivery` | 订单号/批次/联系人/电话/地址/状态 | 配送 |

- CSV 带 **UTF-8 BOM**，Excel 打开中文不乱码；
- 字段含逗号/引号/换行时按 RFC 4180 转义；
- 后台「厨房生产」「订单」页面各加了导出按钮，前端先 `fetch` 带令牌再触发下载（不能直接 `<a href>`，否则丢鉴权头）。
