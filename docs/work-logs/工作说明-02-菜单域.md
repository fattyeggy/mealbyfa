## 2. 完成内容

### 2.1 数据表（新增 7 张）

| 表 | 作用 | 关键约束 |
|---|---|---|
| `meal_ingredient` | 食材主数据：采购/使用单位、换算率、可食率、烹饪损耗、过敏原、移动加权价 | 名称唯一 |
| `meal_dish` | 菜品主数据 + 保存/复热/额外过敏原 | 名称唯一 |
| `meal_dish_version` | 菜品版本：营养、净重、成本、状态 | `(dish_id, version)` 唯一 |
| `meal_recipe_bom` | 每份菜品的可食生重 | `(dish_version_id, ingredient_id)` 唯一 |
| `meal_week_menu` | 周菜单头：主题、地区、起止日、版本、状态、标准成本 | `(start_date, version)` 唯一 |
| `meal_menu_day` | 服务日汇总：重量、蛋白、热量、营养点 | `(menu_id, service_date)` 唯一 |
| `meal_menu_meal` | 餐次 → 菜品版本 + 配送批次 | `(menu_day_id, meal_type)` 唯一 |

### 2.2 接口（新增 16 个）

**后台 · 食材**
`GET/POST /admin/meal/ingredients`、`GET/PUT/DELETE /admin/meal/ingredients/{id}`

**后台 · 菜品**
`GET/POST /admin/meal/dishes`、`GET/PUT /admin/meal/dishes/{id}`、`GET/POST /admin/meal/dishes/{id}/versions`

**后台 · 周菜单**
`GET/POST /admin/meal/menus`、`GET/PUT /admin/meal/menus/{id}`、`PUT /admin/meal/menus/{id}/meals`、`GET /admin/meal/menus/{id}/check`、`POST /admin/meal/menus/{id}/publish`、`POST /admin/meal/menus/{id}/copy`

**小程序 · 公共菜单（免登录）**
`GET /app/menu/week?date=`、`GET /app/menu/weeks`

### 2.3 已实现的业务规则

| 规则 | 落地方式 |
|---|---|
| 成本 = 采购单价 × 可食生重 ÷ 可食率 | `IngredientCostCalculator`，用 BigDecimal 精确计算，单位不支持直接报错 |
| 单位换算（采购单位 → 使用单位） | `conversionRate` + 使用单位折克因子（g/kg/斤/两） |
| 一个自然周 7 天 21 餐次 | 建菜单自动生成 7 个服务日；餐次按早/午/晚校验 |
| 开始日必须是周一 | 创建与复制时校验 |
| 版本唯一 | `(start_date, version)` 唯一索引 + 前置查重 |
| 发布后不可原地修改 | 所有写操作在非 DRAFT 状态直接拒绝（code 1104） |
| 发布前检查 6 项 | 21 餐次 / BOM 完整 / 营养与重量范围 / 过敏原与复热 / 成本率 / 厨房产能 |
| 只能引用启用中的菜品版本 | 写入餐次时校验版本状态 ACTIVE |
| 未发布不泄露草稿 | 公共接口只返回已发布内容，未发布只给预计发布时间 |
| 过敏原由 BOM 推导 | 食材过敏原 ∪ 菜品额外声明，去重后返回 |
| 版本冻结 | 新建版本时归档旧 ACTIVE 版本，成本与营养随版本固定 |

### 2.4 配送批次口径

按手册 §9「晚餐批次配送晚餐与次日早餐」：早餐与晚餐归 `BATCH_2`，午餐归 `BATCH_1`。早餐因此随前一日晚餐送达，需冷食或短时复热——与设计稿中「冷食或短时复热」一致。

## 3. 关键决策与本轮新增假设

| 项 | 决策 | 说明 |
|---|---|---|
| 发布前检查阈值 | 落在 `meal.menu-check.*` 配置 | 手册要求「在允许范围」但未给数值。默认：全天 1200–2200g、蛋白 80–180g、热量 1400–2600kcal、成本率预警 40%。**待业务确认** |
| 成本率检查状态 | 未填成本率时为 `MANUAL`，不阻止发布 | P1 无定价规则，算不出收入；管理员可手填预计成本率参与校验 |
| 厨房产能检查 | 恒为 `MANUAL` | 设备与产能无法由数据自动判定，留人工确认 |
| 人工确认项是否阻断发布 | 不阻断 | 只有 `FAIL` 阻断；`MANUAL` 记录在检查结果中，符合「第一阶段以人工调整为主」 |
| 预计发布时间 | 该周开始日前的周五 08:00 | 手册只说「显示预计发布时间」，未给规则。**待业务确认** |
| 营养点 | 蛋白质克数 ÷ 10，保留 2 位 | 手册「1 点约代表 10g 计划蛋白质」；单价属于 P2 定价规则 |
| 草稿是否对外可见 | 不可见 | 避免未定稿菜单出现在用户端 |

### 4.3 本轮发现并修复的缺陷

| 缺陷 | 现象 | 修复 |
|---|---|---|
| 公共菜单被登录拦截 | `/app/menu/**` 命中鉴权拦截器，未注册用户拿不到菜单，与手册 §3 冲突 | 拦截器放行公共菜单路径 |
| 中文响应乱码 | `getContentAsString()` 按 ISO-8859-1 解码，测试断言失败；部分客户端可能显示乱码 | 强制 `server.servlet.encoding.charset=UTF-8` + `force=true` |
| 草稿内容外泄 | 未发布周会把草稿菜品返回给用户 | 公共接口只返回已发布内容，草稿仅返回预计发布时间 |
| 复制菜单类型错误 | 复制时服务日映射 Map 键类型写成 Long | 改为 `Map<LocalDate, MenuDayDO>` |
