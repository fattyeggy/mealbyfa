# 工作说明 27 · 微信手机号认领（移除手填手机号）

**日期**：2026-11-16
**依据**：委托方「onboarding 第二步不要认领档案，通过微信登录获取手机号实现」

## 改动

- 建档第 2 步删除手机号输入与手填绑定；
- 首次进入的介绍页新增「微信手机号一键认领档案」按钮（`open-type="getPhoneNumber"`）；
- 后端新增 `POST /app/auth/wechat-phone`：
  - code 换微信 access_token，再调 `getuserphonenumber` 取手机号；
  - 手机号匹配后台占位会员后，合并档案、钱包、券、订单并删除占位会员；
  - mock 模式下允许 11 位手机号直接作为 code，便于本地验证；
- 保留 `bind-phone` 供后台/调试使用。

## 实测

- 后台按手机号 13900002222 建档：档位 80g / 1730 kcal；
- 新微信用户登录后调用 wechat-phone（mock code=手机号）→ 返回手机号并绑定成功；
- 未在真机走微信官方手机号授权（需要已认证小程序与真机）。

## 验证

- 后端 126 项测试；
- 小程序 type-check、微信构建通过。

## 补充（同日）：改为启动自动判定

- 新增 `GET /app/auth/status`：返回 `phoneBound`、`onboardingCompleted`；
- 小程序打开即调用：
  - 已绑手机号且已建档 → 直接进首页；
  - 已绑手机号未建档 → 正常进建档；
  - 未绑手机号 → 立即弹出全屏微信手机号授权（不藏在第二步、没有单独页面）；
- 授权成功后自动认领；已建档的直接进首页，新用户继续建档；
- 微信规则限制：手机号必须由用户点一次 `getPhoneNumber` 按钮，无法完全静默；这里已做到「打开即弹、授权即走」。
