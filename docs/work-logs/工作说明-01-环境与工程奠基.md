## 3. 关键决策与本轮新增假设

### 3.1 架构决策

| 编号 | 决策 | 理由 |
|---|---|---|
| ADR-001 | 后端为**独立可启动**的 meal 服务，包名/响应体/鉴权头/审计字段按 RuoYi 约定组织，内部不依赖 RuoYi 编译产物 | 本机无 MySQL/Redis/Docker，RuoYi 单体无法启动验证；「能跑的代码」优先于「像 RuoYi 的目录」 |
| ADR-002 | 一份 DDL 同时跑 MySQL 8 与 H2(MySQL 模式)，只用两者交集语法 | 避免生产库与测试库 schema 漂移 |
| ADR-003 | 微信登录、支付、令牌存储均以接口隔离，mock 实现用配置开关切换 | 生产接入时不改业务代码 |

### 3.2 补充决策（本阶段实际遇到的问题）

- **次级索引与建表脚本分离**：MySQL 8 不支持 `CREATE INDEX IF NOT EXISTS`，H2 不支持 MySQL 的 `KEY idx (col)` 内联写法。为保持「一份 DDL」同时可用，`schema.sql` 只保留建表与唯一约束（两者通用），普通索引放 `mysql-indexes.sql` 由生产部署执行。H2 测试库数据量小，无索引不影响正确性。
- **端点域隔离**：令牌只认证「是谁」，还需限制「能进哪个域」。`AuthInterceptor` 在认证后校验 `/admin/**` 仅后台账号、`/app/**` 仅会员，越权返回 403，避免两类令牌互通。
- **404 语义**：Spring Boot 3.2+ 对未匹配路径抛 `NoResourceFoundException`，原实现被兜底成 500。已单独处理，返回 `code=404`。
- **默认后台账号**：首次启动由 `AdminUserInitializer` 创建 `admin/admin123`（BCrypt 存储），并打 WARN 日志。**部署到测试或生产前必须改密**。

### 3.3 待业务确认（不阻塞开发）

- 营养点单价与基础价的换算公式手册未给出具体数值，P2 将落到 `meal_pricing_rule` 配置表并单列确认项。
- 锁单截止时间按手册设为「前一日 12:00」，是否需要按时区/节假日调整待确认。

## 5. 偏离手册之处

| 项 | 手册要求 | 本期实现 | 说明 |
|---|---|---|---|
| 后端形态 | RuoYi-Vue-Pro 单体版 | 独立 meal 服务 | 环境无法运行 RuoYi；接入契约见 ADR-001 与计划 §4.4 |
| 数据库 | MySQL 8 + Redis | H2 文件库 + 内存令牌 | 同上，生产切 MySQL/Redis 只需改配置与实现类 |
| 登录 | 微信 code2Session | mock openid（`mock_` + code） | 无微信 AppID/Secret；开关 `meal.wx.mock-enabled` |
| System/Member/Pay/Mall/ERP 模块 | 复用 RuoYi | 只实现登录与用户最小闭环 | 按手册 §11「自研边界」，通用能力后续接回 |

以上偏离均已记录在 `docs/00-开发计划.md` §2，不影响业务规则实现。
