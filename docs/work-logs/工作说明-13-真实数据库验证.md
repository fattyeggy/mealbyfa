## 2. 过程：换了四条路才跑起来

| 尝试 | 结果 |
|---|---|
| MySQL 官方 CDN 直链（8.4 / 8.0 多个版本） | 全部 404 |
| 国内镜像（清华 / 中科大 / 阿里云） | 403 / 404 |
| Homebrew MySQL bottle 解包运行 | 失败：`Symbol not found: protobuf ... ReadCord`（依赖的 protobuf ABI 不匹配） |
| **Homebrew MariaDB bottle 解包运行** | **成功** |

MariaDB bottle 也踩了两个坑：

1. bottle 内的库路径是占位符 `@@HOMEBREW_PREFIX@@`，Homebrew 安装时才会替换。手工解包后必须用 `install_name_tool -change` 全部重定位到 `/opt/homebrew`；
2. ARM 上改过的二进制签名失效，需要对每个可执行文件与 dylib 执行 `codesign --force --sign -` 做 ad-hoc 签名。

处理完 92 个二进制后，`mariadbd --version` 正常，服务在 3307 端口启动。**全程只写工作区，未改动系统环境。**

## 3. 验证内容

### 3.1 全量建表与索引

```
server_version = 13.0.2-MariaDB
tables = 28
unique_indexes = 25
```

`schema.sql` 与 `mysql-indexes.sql` 一次通过，无语法错误、无字符集问题。

### 3.2 旧库升级迁移

把刚建好的库回退成「P4.5 之前」的形态（删掉定价版本表、复核表、计划与订单的新列、`sys_user.role`），再执行 `migration-p4.5-p4.6-mysql.sql`：

```
MIGRATION OK
plan_new_cols = 5
review_table = 1
sys_user_role = 1
order_new_cols = 4
```

迁移脚本可重复应用到「旧库」场景，列与表均恢复。

### 3.3 后端连真实库跑业务链路

用 `--spring.profiles.active=mysql` 启动（该 profile 关闭自动建表），跑完整链路：

```
[1] 计划 2 蛋白 130g 日价 79 版本 V1.0
[2] 订单 SC20261115140347947 标价 79.0 版本 V1.0
[3] 锁单 成功=1 失败=0
[4] 状态 已锁定 扣款 79.0 快照=True 配送=['BATCH_1','BATCH_2']
[5] 生产批次 3 计划份数 3
[6] 成本 实收 79.0 食材 26.79 总成本 48.26 毛利 30.74
[7] 退款成功，订单转为已退款
```

### 3.4 直接查库核对

```
week_menu=1   menu_meal=21
plan=2        plan_item=42
orders=1 locked=0 refunded=1
ledger=3 pay=1 refund=1 grant=1
snapshot=1    batches=3    audit=4    pricing_versions=1
```

21 个餐次、42 个计划项、1 笔支付 + 1 笔退款 + 1 笔发放的账本、1 份快照、3 个生产批次、4 条审计——数字自洽。

## 4. 顺带修掉的两件事

1. **后端 pom 缺 MySQL 驱动**（上一轮发现，本轮验证生效）：没有它即使给了真实库也连不上；
2. **死表 `meal_pricing_rule`**：P4.5 之后售价改用版本表，该表已无代码引用，从 `schema.sql` 移除，并在迁移脚本末尾加 `DROP TABLE IF EXISTS`。

## 5. 工具化

`scripts/verify-mysql.sh` 重写为 6 步自检：

```
连接检查 → 全量建表 → 构造旧库 → 应用迁移 → 校验列与表 → 打印冒烟命令
```

支持 socket / TCP 两种连接、可用 `MYSQL_CLIENT` 指定客户端，避免把验证步骤绑死在某个环境。

---

## 6. 局限（不掩盖）

| 项 | 说明 |
|---|---|
| 数据库不是 Oracle MySQL | 验证在 MariaDB 13.0.2 上完成，协议与方言兼容，但**不是 MySQL 8 本体**；生产若用 Oracle MySQL，建议再跑一次脚本 |
| 未验证生产网络与权限 | 本地 socket 直连 root，未模拟最小权限账号、连接池上限、慢查询 |
| 未演练备份恢复 | 手册 §16 上线合规里的「每日备份 + 恢复演练」仍未做 |
| 数据量级 | 仅演示数据，未做万级订单的索引与查询性能验证 |
