## 1. 阶段目标

用业务方下发的正式计价规则替换此前「从设计稿反推」的临时定价，并把定价从「可即时覆盖的键值表」升级为**版本化基线**，保证已确认订单不受后续改价影响。

---

## 2. 规则变化

| 维度 | 旧实现（作废） | 新基线（V1.0） |
|---|---|---|
| 计价单位 | 每餐独立定价 | **每服务日**定价，餐价为展示拆分 |
| 公式 | 餐次基础价 + 营养点 × 单价 | 66 + 1.90 × (P−60) ÷ 10 + Σ替换差价 |
| 参数 | `point_unit_price=5`、`base_price.*`、`swap_surcharge=0` | `daily_base_price=66`、`included_protein_g=60`、`extra_protein_price_per_10g=1.90`、`min_daily_price=65` |
| 蛋白范围 | 80–180g | **80–220g**，生成取整数克 |
| 替换 | 统一加价（默认 0） | (替换变动成本 − 原变动成本) ÷ **0.77**，可正可负 |
| 改价影响 | 立即影响所有新计划 | 新版本只影响新计划，已确认订单冻结 |

### 3.3 计价引擎

```
加量蛋白   = max(0, P − 60)
未取整日价 = 66 + 1.90 × 加量蛋白 ÷ 10 + Σ替换差价
参考日价   = max(65, roundHalfUp(未取整日价, 整数元))
替换差价   = (替换变动成本 − 原变动成本) ÷ 0.77
三餐展示价 = 早 25%、午 40%、晚取余额
```

全程 BigDecimal；**整日只在最后取整一次**；三餐拆分后强制校验合计等于日价。

### 3.4 计划与订单

- 计划生成：蛋白取整数克（112.5 → 113）→ 绑定当前生效定价版本 → 计算日价与三餐展示价 → 每餐记录基准成本；
- 计划读取：按计划所绑版本重算日价，后台发布新版本不改变已有计划；
- 替换：成本差 ÷0.77，正负均可，整日只取整一次，替换后重算三餐展示价；
- 订单：标价 = 日价，写入 `pricing_version`、`raw_price`、`swap_difference`；
- 快照：新增定价版本与日价字段，锁单后改价、改 BOM、改菜单都不影响历史订单；
- 单餐展示价只用于展示与成本分析，不开放单餐退款。

### 3.5 人工复核

以下情况置 `needsReview=true` 并记录原因，且**不静默改价或改蛋白目标**：

- 日价触及最低价兜底；
- 计划蛋白超出定价版本范围；
- 某餐次份量缩放超出 0.5–2.0 倍。

存在待复核事项时，下单接口直接拒绝（1208），要求人工处理。

### 4.3 本轮发现并修复的问题

| 问题 | 影响 | 处理 |

| `target` 内出现 61 个「xxx 2.class」 | 重复 Bean 定义、打包报「找不到唯一主类」 | 工作区在 iCloud 同步目录，同步冲突会产生副本；测试脚本改为先 `clean`，并在脚本注释中记录原因 |

## 5. 偏离与待确认

| 项 | 现状 | 说明 |
|---|---|---|
| 0.77 成本折算系数 | 已按文档实现 | 文档注明「不代表最终净利率」，真实收费前需实测校准 |
| 包装是否随份量变动 | 按餐固定，不参与替换差价 | 建议文档明确，避免替换份量变化时口径争议 |
| 自由替换开放边界 | 配置开关 `meal.pricing.allow-unreviewed-swap`，开发默认放开 | 生产应置 `false`，只开放已审核选项 |
| 支付手续费、固定分摊 | 仍是 P4 演示参数 | 文档 §12 要求上线前用经营方确认口径，不能用演示值证明利润 |
