## 2. 菜品与食材界面

新增「菜品与食材」页，两个标签：

| 标签 | 能力 |
|---|---|
| 食材 | 列表/搜索、新建、编辑、删除；字段含采购/使用单位、换算率、**可食率**、移动加权价、保质期、过敏原 |
| 菜品 | 列表/搜索、新建、编辑；「版本 / BOM」抽屉里查看版本列表、新建版本并逐行编排 BOM |

关键设计：

- **可食率**字段旁直接写明「去根、去皮后的可用比例」——它决定成本口径，填错会让毛利失真；
- 版本号由服务端递增，界面不填；
- 没有版本与 BOM 的菜品无法排进菜单，页面文案直接说明这一点。

截图：`docs/screenshots/19-后台-菜品与食材.png`、`20-后台-菜品版本.png`。

## 3. 备份恢复演练（真实执行）

在 MariaDB 13.0.2 上完成完整往返：

| 步骤 | 结果 |
|---|---|
| 全量导出 `mariadb-dump --single-transaction` | 0.4s |
| 恢复到新库 | 1.4s |
| 表数量 | 29 / 29 |
| `meal_menu_meal` / `meal_dish_version` / `meal_order` / `meal_wallet_ledger` / `meal_audit_log` | 21/21、3/3、1/1、3/3、4/4 |
| `CHECKSUM TABLE` 五张核心表 | **完全一致** |

演练中还发现：旧库保留了一张已废弃的 `meal_pricing_rule`，直接整库导入会在 `LOCK TABLES` 处中断后续表。
排除该表后恢复正常——这条已写进部署手册的注意事项。

## 4. 两个真实的坑

### 4.1 构建通过 ≠ 页面能打开

给路由和侧边栏加页面时，替换字符串多带了一个逗号，产生数组空洞：

```js
{ path: 'catalog', ... },,      // 数组里多了一个 undefined
```

`npm run build` **完全通过**（JS 允许数组空洞），但页面白屏，浏览器报
`Cannot read properties of undefined (reading 'path')`。

如果只看构建结果，这个 bug 会直接进交付。教训：前端必须做一次真实渲染验证。

### 4.2 字段名对不上，表格空一列

版本表用了 `versionNo`，而后端字段是 `version`，导致「版本」列全空、成本显示 ¥13.6126。
改为 `version` 并把成本格式化为两位小数后正常。
