## 1. 阶段目标

把已发布的周菜单变成「某个用户的一周个人计划」：Onboarding 建档 → 目标营养估算 → 逐餐等比缩放到个人份量 → 营养点计价 → 蛋白替换试算与提交，并对过敏原做拦截。

### 2.3 计价公式

```
营养点（单餐） = 该餐目标蛋白质 ÷ 10
单餐价格       = 餐次基础价 + 营养点 × 营养点单价 + 替换加价（仅替换时）
```

默认值（全部在 `meal_pricing_rule` 表中，后台可改）：

| 键 | 默认值 | 含义 |
|---|---|---|
| `point_unit_price` | 5.0000 | 每营养点 5 元 |
| `base_price.BREAKFAST` | 4.0000 | 早餐基础价 |
| `base_price.LUNCH` | 11.0000 | 午餐基础价 |
| `base_price.DINNER` | 5.5000 | 晚餐基础价 |
| `protein_swap_surcharge` | 0.0000 | 替换加价（默认不加价） |
| `min_price` | 0.0000 | 单餐最低价 |

用设计稿的示意数据验算：早餐 2.8 点 → 4 + 14 = **18.00 元**；午餐 4.2 点 → 11 + 21 = **32.00 元**；晚餐 4.5 点 → 5.5 + 22.5 = **28.00 元**。三组结果与设计稿的 18 / 32 / 28 完全一致，默认值即由此反推。

### 2.4 目标营养口径

- 基础代谢：Mifflin-St Jeor
- 总消耗：基础代谢 × 活动系数（1.2 / 1.375 / 1.55 / 1.725）
- 目标热量：减脂 −400 kcal、维持 0、增肌 +300 kcal
- 目标蛋白质：减脂 1.8 g/kg、维持 1.5 g/kg、增肌 1.8 g/kg，乘食量系数（0.9 / 1.0 / 1.1），夹在 **80–180 g**
- 三餐分配：早餐 25%、午餐 40%、晚餐 35%

**这是规则化初稿，不是营养处方**。手册 §5 要求「系统生成初始计划；人工营养规则校验后进入个人首页」，因此结果定位为待运营复核的计划草稿。

### 2.5 个人份量算法

每餐按 `目标蛋白质 ÷ 菜品蛋白质` 等比缩放克重与热量，营养点与价格随之重算；缩放比例夹在 **0.5–2.0**，避免出现不可执行的极端份量。替换蛋白时目标蛋白质保持不变，因此营养点恒定，只有配置了替换加价才会影响价格。

### 2.6 过敏拦截

菜品过敏原 = BOM 食材过敏原 ∪ 菜品额外声明。换蛋白时若与用户过敏原相交，直接拒绝（code 1206）；生成计划时若菜单本身含过敏原，则标记 `allergenConflict` 并在周计划 `warnings` 中提示，供 P3 下单时阻断。

## 3. 关键决策与本轮新增假设

| 项 | 决策 | 说明 |
|---|---|---|
| 计价公式与数值 | 落库可配，默认 5 元/点 + 餐次基础价 | 手册未给公式；默认值由设计稿 18/32/28 反推得出，**待业务确认** |
| 目标营养算法 | Mifflin-St Jeor + 目标调整 + 食量系数 | 属初始假设，人工复核后才生效 |
| 三餐分配比例 | 25% / 40% / 35% | 手册未给 |
| 蛋白替换是否加价 | 默认不加价 | 营养点由目标蛋白质决定，替换后不变；加价规则留配置位 |
| 计划重建 | 同周重生成时版本 +1，旧版本逻辑删除 | 保留可追溯性，为 P3 订单快照做准备 |
| 缩放边界 | 0.5–2.0 | 防止极端份量 |

## 5. 偏离手册之处

| 项 | 手册 | 本期 | 原因 |
|---|---|---|---|
| 定价公式 | 只给方向 | 基础价 + 营养点 × 单价，默认值反推自设计稿 | 手册无公式与数值 |
| 人工营养校验 | 「人工营养规则校验后进入个人首页」 | 未做校验工作流，仅产出草稿 | 人工流程属于运营后台能力，P6 补 |
| 蔬菜 500–1000g/日 | §1 已确认决策 | 未纳入计划生成约束 | 待菜单侧补充蔬菜字段后加校验 |
| 蛋白偏好 | 建档项 | 仅存储，未参与推荐 | 推荐算法属运营策略，待确认 |
