**结论**：已从「按蛋白整体放大」改为「按组件分别缩放」，基准用户热量回到目标区间；不可行的组合会进入人工复核

## 1. 问题复核

Claude 的判断成立：截图用户全天目标 1630 kcal，只订午晚两餐实际已 1818 kcal，
原因是 `factor = 目标蛋白 ÷ 菜品蛋白` 后重量/热量/碳水/脂肪同比例放大。

## 2. 实现

### 2.1 数据模型

- `meal_ingredient` 增加：`component_type`（PROTEIN / STAPLE / VEGETABLE / FAT / OTHER）
  与每 100g 的 `kcal/protein/carb/fat`；
- 录入食材时一并录入，菜单 BOM 即可自动拆组件。

### 2.2 缩放算法（ComponentPortioner）

- 蛋白主料跟蛋白目标、主食跟碳水目标、油脂跟脂肪目标、蔬菜固定；
- 解三元一次方程同时满足 P/C/F：
  ```
  P: a1·fp + b1·fc + c1·ff = 目标蛋白 − 蔬菜
  C: a2·fp + b2·fc + c2·ff = 目标碳水 − 蔬菜
  F: a3·fp + b3·fc + c3·ff = 目标脂肪 − 蔬菜
  ```
- 因子夹在 0.30–2.50；单餐克重上限 750g；
- 无组件数据时自动回退旧的等比缩放（兼容老菜单）。

### 2.3 全天约束与复核

- 热量 ±5%、蛋白 ≥95%、碳水/脂肪 ±10%；
- 超差生成 `MACRO_DEVIATION` 复核事项；
- 份量触界生成 `SCALE_CLAMP`；
- 不再静默放行。
