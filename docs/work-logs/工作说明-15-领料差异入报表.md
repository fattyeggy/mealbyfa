## 1. 目标

成本报表此前只有**理论成本**：采购价、包装、配送都有，唯独「实际领了多少、损耗多少」没有进报表。手册 §16 要求「采购价、领料、损耗、包装配送正确进入成本」，这一项一直挂着 ⚠️。

---

## 2. 第一版做错了，当场改掉

第一版把「实际用料」按当天所有领料累加，与「理论用料（全天 BOM）」相比。真实环境跑出来是这样：

```
理论用料 ¥27.83  实际用料 ¥14.43  差异 ¥-13.4
```

看起来像「省了 13 块」，其实是**拿全天理论值去比部分登记的实际值**——领料只登记了一种食材，必然显示出巨大负差。这种数字比没有更危险。

改成**同口径比较**：只比「已登记领料」的食材，理论取该食材的 BOM 推导成本，实际取其领料成本。

```
食材 味噌三文鱼P1 理论可食 168.0g 成本 ¥12.03
已登记口径：理论 ¥12.03  实际 ¥14.43  差异 ¥2.40 已登记=True
```

多领 20%，差异 +2.40，这才是运营能用的信号。

## 3. 实现

| 层 | 改动 |
|---|---|
| 用料需求 | `MaterialDemandResp.Item` 增加 `actualCost`，按领料克重折算 |
| 成本报表 | `DayRow` 增加 `materialTheoreticalCost` / `materialActualCost` / `materialDiff` / `hasMaterialIssue` |
| 口径 | 只聚合 `actualCost != null` 的食材；无登记时差异为 `null` 而非 0 |
| 取整 | 先各自取整到分，再相减，保证「差异 = 实际 − 理论」恒等 |
| 后台 | 成本页新增「理论用料（已登记）/ 实际用料 / 用料差异」三列，超支标红 |
