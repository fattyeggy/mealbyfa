### 2.3 生产合并口径

生产线不看订单，看批次：

```
已锁订单 × 订单明细 → 按 (配送批次, 菜品版本) 分组 → 计划份数
```

早餐与晚餐归 `BATCH_2`（晚餐与次日早餐同一批次），午餐归 `BATCH_1`。重复执行 `generate` 会按最新订单重算份数，但保留已登记的实做与损耗；订单取消后不再需要的批次，只有在未开工且无实做记录时才删除。

### 2.4 食材需求算法

```
理论可食生重 = Σ(订单明细克重 ÷ 菜品标准净重 × BOM 可食生重)
采购重量     = 理论可食生重 ÷ 可食率
金额         = 采购单价 × 采购重量
```

**必须按个人份量折算**：同一菜品的不同用户克重不同（例如标准 720g 的午餐在 45g 蛋白目标下会放大到 926g），若直接按标准 BOM × 份数计算，会系统性低估约 7%。本轮已修正为按订单实际克重折算。

### 2.5 三层成本（§10）

| 层 | 口径 |
|---|---|
| 食材成本 | 订单明细的 `cost` 之和（锁单时已按个人份量固定） |
| 包装分摊 | 餐次数 × 每餐包装 |
| 配送分摊 | 订单数 × 每单配送（含两次配送） |
| 附加 | 支付手续费 = 实收 × 费率；固定成本 = 订单数 × 每单分摊 |

报表同时给出「食材成本率」与「总成本率」，并保证 `总成本 = 各项之和`、`毛利 = 实收 − 总成本`，测试中对账。

## 3. 关键决策与本轮新增假设

| 项 | 决策 | 说明 |
|---|---|---|
| 包装 2 元/餐、配送 12 元/单、手续费 0.6%、固定 3 元/单 | 初始默认值，台账可改 | 手册未给数值，**待业务确认** |
| 食材成本用订单明细 cost 而非领料实际 | 报表口径以「锁单时成本」为准，领料差异单独看 | 实际成本需盘点后才准确，第一阶段先对理论值 |
| 临时替换只记录、不改快照 | 快照是契约，替换是履约偏差 | 必须留审批人与用户通知状态（手册 §9） |
| 替换时校验过敏原 | 命中用户过敏原直接拒绝 | 防止通过替换绕过过敏拦截 |
| 退款释放订单唯一槽位 | 与取消口径一致 | 修正了 P3 的一处不一致 |
