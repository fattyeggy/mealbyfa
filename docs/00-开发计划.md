# 三餐私教 开发计划

**依据**：《三餐私教微信小程序与 RuoYi 后台开发交接手册 V1.0》（2026-11-15）
**项目**：在线三餐私教（河南省新乡市），个性化三餐计划 + 制作 + 配送
**代码库**：`sancan-coach/`
**编制日期**：2026-11-15

---

## 1. 目标与边界

按手册「开发启动顺序」（§18）推进，交付一条可运行的完整业务链：

> 周菜单发布 → 用户 Onboarding → 个人计划生成 → 营养点计价与蛋白替换 → 优惠券与 credit 扣款 → 锁单快照 → 生产汇总与食材需求 → 两次配送 → 完餐反馈。

**本期做**：手册 §1 已确认决策范围内的全部自研部分。
**本期不做**（与手册一致）：抖音小程序、骑手地图与自动派单、多商户与加盟结算、医疗营养处方、拼团秒杀砍价分销、中央厨房 MES、真实微信支付（第一阶段）。

## 2. 环境约束与架构决策

当前开发机可用环境：

| 项 | 状态 |
|---|---|
| Node.js | v24.14.0 ✅ |
| PostgreSQL | 16.15 运行中 ✅ |
| 网络（GitHub / Maven Central / npm） | 可达 ✅ |
| JDK / Maven | ❌ 系统未安装 → 已落地便携版到 `tools/` |
| MySQL / Redis / Docker | ❌ 均未安装 |

### ADR-001 后端形态：独立 meal 服务 + 可回挂 RuoYi

**决策**：本期交付一个可独立启动的 `sancan-meal-service`（Java 17 + Spring Boot 3 + MyBatis-Plus），包结构、响应体、鉴权头、审计字段全部按 RuoYi-Vue-Pro 约定组织；`meal` 模块内部不依赖 RuoYi 任何模块的编译产物。

**理由**：
1. 本机无 MySQL / Redis / Docker，完整 RuoYi 单体无法启动与验证；交付出「能跑、能测」的代码优先于「目录结构看起来像 RuoYi」。
2. 手册 §11 的结论本身就是「复用 RuoYi 通用能力，自研 meal 模块」。把 meal 做成零外部依赖的模块，正是让它可以整包迁入 `yudao-module-meal`。
3. 接入 RuoYi 的适配点（登录、CommonResult、MyBatis-Plus、Redis 令牌、微信支付）都在接口边界上，已用接口隔离，见 §4.4。

**代价**：System / Member / Pay / Mall / ERP 不被真实复用，本期以最小实现替代；真实接入时替换实现类即可，业务代码不动。

### ADR-002 数据库：一份 DDL 同时跑 MySQL 8 与 H2

**决策**：建表脚本只用 MySQL 8 与 H2(MySQL 模式) 的交集语法（不用 `ENGINE=`、不用内联 `COMMENT`、不用函数索引与生成列），本机用 H2 文件库跑测试，交付时同一份脚本可直接导入 MySQL。

**理由**：避免维护两套 schema 造成生产与测试漂移。**代价**：放弃 MySQL 专有语法；如确需用到（如 JSON 列），单独用方言分支并在此登记。

### ADR-004 定价版本化（P4.5 起）

**决策**：售价参数不再用可即时覆盖的键值表，改为 `meal_pricing_version` 版本表 + 发布流程；计划与订单绑定版本号，历史订单可解释其价格来源。

**理由**：业务方《计价规则与开发验收 V1.0》要求「调整参数必须产生新的定价版本，不能修改已确认或已锁定订单」。旧键值表无法支撑审计。

**代价**：改价需要「新建草稿 → 复核 → 发布」三步，不能再一键覆盖。

### ADR-003 外部依赖可替换

| 外部能力 | 本期实现 | 生产替换 |
|---|---|---|
| 微信登录 | `WxAuthProvider` 的 mock 实现（固定 openid 映射） | `code2Session` 真实调用 |
| 微信支付 | `PayGateway` 沙箱实现（仅记账，不发起真实支付） | 微信小程序支付 V3 |
| 令牌存储 | 内存 `TokenStore` | Redis |
| 对象存储 | 本地文件 | 兼容 S3 / 国内云 |

所有 mock 实现都带 `@ConditionalOnProperty`，切换开关即可，不删代码。

## 4. 工程结构

```
sancan-coach/
├── backend/                     # sancan-meal-service
│   ├── pom.xml
│   └── src/main/java/com/sancan/meal/
│       ├── common/              # 统一响应、异常、分页、审计、鉴权

│       ├── member/              # 小程序用户

│       ├── pricing/             # 营养点计价引擎
│       ├── wallet/              # 账户与不可删账本
│       ├── coupon/              # 券模板与用户券
│       ├── order/               # 订单、锁单、快照
│       ├── kitchen/             # 生产汇总、领料、分装标签
│       ├── cost/                # 食材成本、三层成本报表
│       └── feedback/            # 完餐反馈与周复盘
├── miniapp/                     # 微信小程序（UniApp）
├── admin/                       # 运营后台（Vue3）
├── docs/
│   ├── 00-开发计划.md
│   ├── adr/
│   └── work-logs/               # 每阶段工作说明
├── scripts/                     # 一键启动、测试、建库
└── tools/                       # 便携 JDK 与 Maven（不提交仓库）
```

### 4.4 RuoYi 接入契约

| 契约点 | 本项目 | 迁入 RuoYi 时 |
|---|---|---|
| 包名 | `com.sancan.meal.*` | `cn.iocoder.yudao.module.meal.*` |
| 响应体 | `CommonResult{code,data,msg}` | 直接复用 `CommonResult` |
| 鉴权头 | `Authorization: Bearer {token}` | 复用 `TokenAuthenticationFilter` |
| 审计字段 | `creator/create_time/updater/update_time/deleted` | 直接复用 `BaseDO` |
| 权限点 | `meal:menu:publish` 形式 | 复用 `@PreAuthorize` + 菜单表 |

## 6. 数据模型清单（对应 §12）

`meal_` 前缀，共 24 张表：

| 域 | 表 |
|---|---|
| 菜单 | `meal_week_menu`、`meal_menu_day`、`meal_menu_meal`、`meal_dish`、`meal_dish_version`、`meal_recipe_bom` |
| 主数据 | `meal_ingredient`、`meal_pricing_rule` |
| 用户 | `member_user`、`meal_user_profile`、`meal_nutrition_plan`、`meal_plan_item` |
| 交易 | `meal_order`、`meal_order_snapshot`、`meal_wallet_account`、`meal_wallet_ledger`、`meal_coupon_template`、`meal_coupon` |
| 后场 | `meal_production_batch`、`meal_production_record`、`meal_delivery` |
| 反馈 | `meal_feedback` |
| 平台 | `sys_user`、`sys_role`、`meal_audit_log` |

**硬约束**（§12 数据约束，用唯一索引与触发器/服务校验双保险）：
- `uk_order_user_service_date`：用户 + 服务日唯一 → 锁单幂等
- `uk_menu_version`：周菜单 + 版本唯一，发布后不可原地覆盖
- 账本表只允许 INSERT，冲正反向关联原流水
- 快照只在锁单事务内创建一次

## 7. 验收映射（对应 §16）

| 手册验收项 | 落地方式 |
|---|---|
| 21 餐次完整、营养在范围 | 发布前检查接口 + 单元测试 |
| 余额不足不锁单 | 锁单事务测试 |
| 重复锁单只成功一次 | 唯一索引 + 并发测试 |
| 重复支付回调不重复入账 | 回调幂等测试 |
| 人工调余额必须留流水且不可删 | 账本只 INSERT + 测试 |
| 赠送 credit 不退成现金、不产生正式积分 | 退款来源路由测试 |
| 历史订单不随菜单/价格变化 | 快照不可变测试 |
| 过敏原阻止下单 | 下单校验测试 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 手册未给出定价公式细节 | 计价口径可能与业务预期不符 | 计价规则全部落 `meal_pricing_rule` 表可配，公式写入文档并在工作说明中列为待确认项 |
| 完整 RuoYi 无法本机验证 | 接入时可能有适配工作量 | 接口边界隔离 + §4.4 契约表 |
| 营养规则含人工判断 | 自动化决策风险 | 只做规则校验与建议，最终由人工确认（与手册 §5 一致） |
| 小程序预览需真机/浏览器 | 视觉验证受限 | H5 预览 + 截图比对设计稿 |

## 9. 工作说明规范

每阶段产出一份 `docs/work-logs/工作说明-NN-<阶段>.md`，固定结构：

1. **阶段目标**与进入条件
2. **完成内容**（文件、接口、表结构清单）
3. **关键决策与本轮新增假设**
4. **验证结果**（测试数量、通过率、关键测试名、构建产物）
5. **偏离手册之处**（如有，逐条说明原因）
6. **遗留问题与下一阶段入口**
